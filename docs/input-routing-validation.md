# v0.6.2 鼠标关联验证

本版本修复诊断与结果判定，不代表 OPPO 真机已验证，也不代表连续跨屏已实现。

## 修复内容

- 通过 IInputManager Binder 直接枚举和读取设备，避免异步缓存导致错误读回。
- 外接判定使用 isExternal，排除虚拟设备；Location 仅用于端口回退。
- 每级关联等待最多 1.5 秒，按 descriptor 匹配重新枚举后的设备。
- 写入返回但读回未生效时撤销该映射，再进入下一级；撤销失败停止该设备的回退。
- RESULT_OK 仅由所有目标鼠标的关联读回决定，接口无异常不算功能成功。
- 解除关联不再处理内置触摸屏和纯键盘；保留端口解除失败原因并读回。

## 真机步骤

1. 安装 release APK，重新启动 Shizuku 服务连接，保持鼠标及物理外屏连接。
2. 查看输入设备列表，保存完整输出；关注 external、virtual、mouse、descriptor、associatedDisplayId。
3. 绑定输入到外屏，保存全部回退输出和 RESULT_OK。外接屏 ID 必须由当前枚举取得。
4. 无论 RESULT_OK 如何，都单独记录外屏光标是否可见、移动、点击、右键、滚轮是否正常。
5. 如果光标可操作外屏，再测试 Moonlight pointer capture / relative mouse mode。
6. 解除输入关联，保存 RESULT_OK 与读回结果，确认鼠标返回内屏。

## 结论边界

输入关联是每个设备到单块屏幕的映射，不建立两屏连续坐标空间。读回成功只证明关联状态，不能证明光标可见、Moonlight 可用或鼠标可以跨屏滑动。

如果同一个 InputDevice 同时包含鼠标和键盘，设备级关联无法只选择其中的鼠标部分；需要同时测试键盘焦点行为。

在 topology flag 关闭且没有厂商额外接口的前提下，现有 shell Binder 接口没有暴露创建原生连续坐标空间的通道。不能把定时切换关联包装为 Windows / DeX 原生跨屏。

交接文档中“整个路径不存在于编译产物”不是已做 ROM 二进制检查的结论。源码可以证明 flag 关闭时 coordinator 不创建、get 返回 null、set 不处理；是否被编译器删除，需要单独检查 ROM 产物。
