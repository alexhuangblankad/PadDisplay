# PadDisplay 1.0.3 桌面使用与验证

本版独立实现桌面工作流程，没有移植 VoyageOS 的代码、资源或付费验证。

## 开始

1. 安装 release APK，启动并授权 Shizuku。
2. 接入物理外屏和鼠标。桌面内置 Dock 不依赖悬浮权限；跨应用 Dock 如未显示，在高级设置允许悬浮显示。
3. 点击“开启主机”。内屏保留应用网格，外屏显示壁纸、时钟、本机应用快捷方式和完整任务栏。外屏“应用”或 Dock 的网格按钮打开启动台。
4. 点击应用打开到外屏；星标收藏会保存，可在任务栏快速启动。
5. 内屏电源按钮位于首页。其它操作统一在“高级设置”，按桌面与外观、显示、音频、窗口、诊断分类。

## 窗口和缩放

默认为应用请求自由窗口，可在高级设置关闭此选项；系统必须实际支持 freeform。桌面自身单独要求全屏，不改变整块显示器窗口策略。窗口页读取真实任务，可聚焦、关闭、切换全屏与恢复窗口；仅真实自由窗口允许左右排列、居中、放大、缩小和移动。可见 freeform 窗口提供标题条与右下角调整手柄，拖动松开后提交实际边界并验证；红色关闭、黄色返回桌面、绿色全屏。全屏任务另有恢复窗口控制条。系统拒绝操作时显示失败，不模拟窗口；黄色按钮不等于真正最小化。

任务栏可打开控制中心，提供真实媒体音量、平板亮度、Wi-Fi / 蓝牙系统设置与主题切换。平板亮度依赖 shell 可访问的系统接口，不控制外接显示器硬件背光；不可读取时禁用滑条。显示和音频详细设置保持原来的确认流程。

右下角返回键向目标物理外屏发送返回；Home 返回 PadDisplay 外屏桌面，多任务打开外屏窗口列表。浮层不覆盖屏幕两侧，不设置系统手势排除区域，应用侧边返回依然由 ROM 派发。桌面自身是工作空间根页面，返回不会退出主机；全屏应用可以通过窗口控制条恢复窗口。Moonlight 自动隐藏全部浮层。

全屏串流时，可在高级设置打开系统辅助设置并启用“PadDisplay 全屏导航快捷键”。该服务仅在主机运行期间处理无 Ctrl / Alt / Shift 修饰的 F9；Fn 由键盘固件决定，只有上报 F9 时才能触发。左 Alt 与其它键不会被消费，不模拟鼠标、不启用触摸探索、不读取窗口内容。F9 唤出底部中央导航对话框，临时获取外屏焦点，15 秒后退出；点击返回先关闭面板，再把返回发到外屏应用。高级设置另有手动唤出按钮。真实 Moonlight / UU 指针捕获的恢复行为需真机测试，不因 UI 检查成功就宣称任意全屏场景均可退出。

全屏/恢复窗口使用系统 WindowContainerTransaction，再读回实际任务模式。接口来自 [AOSP WindowContainerTransaction](https://github.com/aosp-mirror/platform_frameworks_base/blob/android16-release/core/java/android/window/WindowContainerTransaction.java) 与 [IWindowOrganizerController](https://github.com/aosp-mirror/platform_frameworks_base/blob/android16-release/core/java/android/window/IWindowOrganizerController.aidl)。

外屏缩放支持 75%、100%、125%、150%、200%。改变的是外屏 DPI，而非 4K 信号分辨率；15 秒内确认，否则恢复。确认比例按显示器保存。退出桌面恢复原 DPI，下次开启重新应用保存比例。

Moonlight 位于前台时可自动隐藏任务栏；不转发、抓取或注入鼠标事件。任务栏隐藏与前台任务轮询有关，可能有约 3 秒延迟。

## 鼠标与恢复

原生鼠标绑定按 descriptor、port uniqueId、port 三条路径逐级尝试，读取实际 AssociatedDisplayId 验证。键鼠复合设备可能同时改变键盘归属。绑定成功只代表固定到外屏，不代表鼠标可以滑过内外屏边缘。

退出撤掉外屏桌面和所有浮层，仅尝试将本次会话启动的应用迁回内屏，跳过共享其它应用的根任务、恢复 DPI，让系统恢复刚连接显示器的效果；不额外强制镜像。退出、外屏断开、客户端 Binder 死亡时先点亮内屏，清理已有鼠标关联，明确将鼠标关联回内屏并读回。用户已反馈此前版本鼠标、缩放、显示正常，新退出与回迁策略还需真机检查。高级设置提供手动“鼠标回平板”。重新进入主机前清理内屏映射，再绑定外屏，避免旧端口映射互相覆盖。

原外屏重新接入可自动恢复，按显示器身份匹配，不硬编码 displayId。Shizuku 被关闭、进程被系统强制终止或 ROM 拒绝权限时，恢复不能保证，诊断应保留实际错误。

## 验证边界

已进行 release 构建、签名校验、DPI 控制与窗口坐标 JVM 检查、Android 35 模拟器亮暗主题、横竖屏与主界面显示检查。桌面壁纸与启动台用独立 instrumentation 视觉夹具预览，注入模拟 UI 状态，不能算作物理外屏或 Dock 功能验证；夹具不打进 release APK。模拟器的虚拟外屏不会绕过物理屏限制。

用户已确认此前基础鼠标、缩放与显示正常；新增外屏浮层、任务聚焦/关闭/调整与回迁、亮度还需 OPPO Android 16 / ColorOS 实测。控制中心实际音量调整在模拟器通过；没有证据证明所有应用都允许外屏或自由窗口。display_topology 未开启的系统没有在本版获得连续双屏鼠标坐标空间。

真机验收建议：先开全屏桌面并启动普通应用，检查鼠标实际位置；再测试窗口模式和 DPI 倒计时；最后测试外屏拔插、退出与 Moonlight 相对鼠标模式。失败时复制内部控制台日志及鼠标三级回退读回结果。

## v1.0.1 前端参考与恢复边界

布局参考三星官方 DeX 与华为 Desktop Mode 文档的常见结构：桌面快捷方式、底部应用 / 任务栏、控制与状态区。没有移植厂商桌面代码或资源。默认 Dock 使用设备实际的 Launcher 应用列表，收藏优先，再选浏览器、文件管理、设置、相册、便签等；没有 Google 服务也可使用。

截图所示竖向桌面通过仅调整自己的桌面任务来处理，清除旧自由窗口边界并读回全屏模式。退出使用 finishAndRemoveTask 加自有任务清理，不留自己的桌面快照任务。退出后厂商再次调度其它应用到外屏的行为没有真机证据，本版不修改厂商策略，不声称已彻底消除。


## v1.0.3 应用配置检查

应用启动前提交外屏 ID、模式和初始逻辑边界，失败时回退原启动路径。窗口页显示应用实际显示器、dp 尺寸、DPI 与 appBounds。3840×2160 输出、外屏 cur 逻辑尺寸、任务 bounds 与应用 appBounds 是不同层次，不应把任一尺寸直接当作自由窗口成功或失败证据。本版没有 ColorOS 真机验证。
