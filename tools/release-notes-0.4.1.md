## 先修两个你骂得对的地方

### 1. 「外接屏卡在设置」是我写死的

看日志就知道，我的"一键完成"最后一步执行的是：

```
am start --display 4 -n com.android.settings/.Settings
```

**我把「设置」这个组件写死了。** 所以你看到的外屏卡在设置、什么都干不了 ——
是我的代码造成的，不是系统。

**本版已移除这一步**：一键开始只负责把外接屏独立出来，
要开哪个应用由你从「打开应用到外接屏」里自己选。

### 2. 你装的是 v0.3.3

日志抬头写着 `PadDisplay v0.3.3`。应用抽屉是 v0.4.0 才有的，
所以"无法打开任何其他 app"里有一部分只是版本没更新。这次一起更新。

## 鼠标问题：我换了一条真正能走通的路

我上一条把话说死了，但漏看了一条线索：参考项目 Dextop 创建的是
**"Dextop Virtual Mouse" / "Virtual Touchpad"** 这类 **uinput 虚拟输入设备** ——
系统**会给真实输入设备画指针**。不过那需要 uinput/JNI，复杂且脆弱。

而 AdaptiveScreenPlus 走的是另一条**已跑通**的路，我按它实现了：

```
系统只给真实鼠标画指针，注入的事件不会点亮它
  → 所以光标必须自己画（外接屏上的 TYPE_APPLICATION_OVERLAY 悬浮窗）

点击/移动靠注入
  → IInputManager.injectInputEvent + MotionEvent.setDisplayId
  → 不能用 input 命令：参考项目实测一条 47ms，拖动会一跳一跳

坐标空间必须从系统侧量
  → dumpsys window displays 的 cur=WxH
  → 不能用 Display.getRealSize()（会被应用兼容缩放污染）
```

### 本版新增「用平板当外接屏的触控板」

主界面新增入口，点开是一个触控板页面：

| 手势 | 效果 |
|---|---|
| 手指滑动 | 外接屏上的**自绘光标**跟着移动，并注入指针移动事件 |
| 轻点 | 在光标处**单击**（注入 DOWN+UP，左键） |
| 右键按钮 | 注入右键 |
| 快/慢 | 调灵敏度 |

**这就是"用平板操作外接屏"的完整闭环。** 它不是"鼠标跨屏"，
但它是非 root 下唯一能让外接屏真正"可操作"的办法。

需要两个权限：
- **Shizuku**（注入指针要 shell 身份）
- **「显示在其他应用上层」**（画光标），页面里有按钮引导去开

## 关于"打包 standby 和 smartdock"

**我没有做，也不建议做**，理由是实的：

1. 它们是别人的 GPL 应用，整包塞进我的 APK 属于再分发，许可与来源都麻烦
2. **打包了也解决不了问题** —— 它们同样依赖被 ColorOS 关闭的
   `DisplayTopology`（要么依赖系统桌面模式），在你这台机器上照样跑不出想要的效果
3. 我自己的「应用抽屉」已经能做"在外屏开任意应用"，
   你要的"两个桌面"这条已经通了

如果你确实想要它们的界面（比如 SmartDock 的任务栏外观），
那应该**单独安装它们**，而不是我打包 —— 我可以帮你看怎么配。

## 请按这个顺序试

1. 升级到本版
2. **① 一键开始** → 现在应该**不会**再打开设置了
3. **「打开应用到外接屏」** → 刷新列表 → 点某个应用的「外屏」
4. **「用平板当外接屏的触控板」** → 启用光标（会给悬浮窗权限）→ 滑动 + 轻点

第 4 步是这次的重点。如果光标出不来，把**事件日志**发我
（里面会写挂光标失败的原因，最常见是悬浮窗权限没给）。
