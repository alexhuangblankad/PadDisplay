v0.1.6: 分辨率/显示模式诊断增强 —— 不再靠"没报错"当成功

## 你反馈的现象，我从日志里读出的硬事实

你给的日志包含非常关键的信息，先说结论：

| 证据 | 含义 |
|---|---|
| `外接屏(displayId=13) windowingMode: FULLSCREEN(1)` | **已经是扩展模式**，不是镜像。我之前"镜像导致改不了分辨率"的假设是错的 |
| `getWindowingMode code: 98 / setWindowingMode code: 99` | 我修的 code 在设备上真的执行了 |
| `显示 3840×2160, displayId=13, 型号 OPD2515` | 你的便携屏是 4K 屏，当前就跑在 4K@60 |
| `切换前 mode=3840×2160@60, size=3840x2160` | **要切的目标和切换前完全一样** |

最后一行是关键：你日志里那次"切换"的目标是 `3840×2160@60`，而外屏本来就在
`3840×2160@60` —— **那次调用本来就是空操作，不是失败**。
"使用最佳分辨率"选出来的就是当前模式。

这暴露了我一个工具性缺陷：**我没办法让你验证"换一个分辨率到底行不行"**。

## 本版修复

### 1. Mode 切换现在会「读回验证」（最重要的诚实性修正）

`RESULT_OK=true` 只代表调用没抛异常，**不代表分辨率真的变了**。
现在每次切换后都会 `getUserPreferredDisplayMode()` 读回比对：

```
调用成功 + 读回一致        → ✅ 成功
调用成功 + 读回不一致      → ❌ 请求未被系统采用（明确报告，不再谎报）
调用失败                  → ❌ 附完整异常
```

### 2. 目标与当前相同 → 明确告知，不再做无意义的"切换"

界面会直接说「外接屏已经是 3840×2160@60，无需切换」，
并提示：**要验证能否切换，请在列表里选另一个分辨率**。

### 3. 新增「Mode 自检」按钮（一键出报告）

一次点出：App 侧看到的当前 Mode / supportedModes 数量 / 可选分辨率、
UserService 侧读回的真实 Mode / 用户首选 Mode / 系统首选 Mode、以及 shell 环境。

### 4. 修掉 shell 命令可能静默失败的问题

`wm` / `dumpsys` 在 `/system/bin` 下，但 Shizuku UserService 进程的 PATH
不一定包含它。早先用 `sh -c "wm size -d N"`，命令可能失败且**无输出**，
于是我读到空字符串、快照变 0×0、回滚机制失效。

现在显式补全 PATH，并**返回退出码**，失败不再伪装成"空输出"。

### 5. 修掉一个状态竞态

`applyBestResolution()` 原来先改 UI 状态、再立刻读状态，可能读到旧值，
导致"最佳分辨率"实际没被应用。现在改为**显式传参**。

### 6. 分辨率列表标出「← 当前」，并在只有一种分辨率时明确说明

避免"点了没反应"的歧义 —— 如果显示器只上报一种 supportedModes，那就真的没得选。

## 关于「复制 / 扩展」的诚实说明

- **「扩展」可实现**：per-display 设独立 FULLSCREEN，并读回 `getWindowingMode` 验证。
- **「复制」本应用不强制切换**：Android 14 起已移除强制镜像的 API
  （`setDisplayIdToMirror` 在 API 34/35/36 的 AIDL 里都不存在）。
  硬做需要改 display 的 enable 状态，有让内屏一并熄灭的风险。
