docs: 补充 11.5 节 —— 用源码证据解释「鼠标跨屏为什么做不到」

## 把这个问题查到底了

用户反复追问「为什么做不到」，这次给出基于 AOSP 源码的确定答案，
并写进 README 永久记录，避免后续再走弯路。

### 这个功能在 Android 里存在，且官方描述就是「光标跨屏」

AOSP frameworks/base/services/core/java/com/android/server/display/feature/display_flags.aconfig
（android-16.0.0_r1）原文：

    flag {
        name: "display_topology"
        namespace: "display_manager"
        description: "Display topology for moving cursors and windows between extended displays"
        bug: "364906028"
        is_fixed_read_only: true
    }

description 明确写着「在扩展显示器之间移动光标和窗口」—— 正是需求本身。

它在系统服务里驱动输入的方式（DisplayManagerService）：

    if (mFlags.isDisplayTopologyEnabled()) {
        DisplayTopologyGraph graph = update.second;
        mInputManagerInternal.setDisplayTopology(graph);   // 喂给输入系统
    }

没有这个 flag，输入系统里就不存在统一的多屏坐标空间，光标不可能跨屏。

### 为什么 App 改不动

is_fixed_read_only: true 的含义（AOSP 官方文档）：
「只读 aconfig 标志是布尔常量，无法在运行时更改。」

配套版本配置里权限为 READ_ONLY。只读标志的值在编译系统镜像时定死，
aflags / device_config 这类运行时开关对它无效（只能改"读写"标志）。

### 结论表

- App / Shizuku 调 API：不可行（服务端 coordinator 为 null，静默空操作）
- aflags enable / device_config put：不可行（只读标志）
- 改系统镜像后重刷（root / 第三方 ROM）：唯一真正可行的办法
- 等厂商后续版本打开该 flag：只能等

即：不是实现难度问题，是厂商在编译时关掉了它。

### 替代方案

不开 root 的前提下：触控板方案（外接屏自绘光标 + 注入指针事件），
见 README 6.9 节与 v0.4.1 实现。
