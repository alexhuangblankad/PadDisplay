v0.6.1: 修掉日志无信息量的问题 —— 改用 shell settings 并打印完整失败原因

## 用户日志暴露的两个实现错误

### 1. -999 是自己的哨兵值，不是真实值

日志里 "development_force_desktop_mode_on_external_displays: -999 -> -999 (写入返回 false)"
中的 -999 是代码里读取失败时返回的占位值，真实含义是"根本没读到这个键"。

### 2. 异常被吞掉（违反任务书第 15 条）

写入走 ContentResolver 且外包 runCatching，抛出的 SecurityException /
IllegalArgumentException 全被吃掉，所以看不到失败原因。任务书第 15 条要求必须打印
完整异常，此前漏做。

## 本版改动

### 1. 改用 shell settings 命令（等同 adb shell settings put）

每行输出包含：
  写入前值（含"键不存在或读取失败"提示）
  命令: /system/bin/settings put global <key> <v>
  输出: <settings 真实输出>
  读回: <实际值>
  失败原因

settings 自身报错（SecurityException / unknown setting / BadUser）会原样显示。

### 2. 新增决定性诊断：全量 dump 搜关键词

执行 settings list global 并搜索 desktop / freeform / multi_window /
resizable / force_desktop：
- 搜到 -> 键存在，属权限或策略问题
- 一条都没有 -> 键在 ColorOS SettingsProvider 中根本未注册，
  即不是权限问题，是 ROM 移除了这些开发者选项

可一次性判定属于哪种情况。

### 3. 顺带报告 settings 命令本身是否可用

（which settings、settings --help 前几行），排除命令环境问题。

## 测试步骤

1. 桌面模式 -> 探测桌面模式能力（看"关键诊断"与"settings 命令是否可用"）
2. 桌面模式 -> 开启桌面模式（看每行的「命令」与「输出」）

## 不预设结论

若 dump 搜不到这些键，说明 ColorOS 从 ROM 层面移除了桌面模式相关开发者选项，
该路线在目标机器上同样不可行，会明确说明并停止在此投入。
若搜到但写入被拒，则可能属权限或策略，另寻可调用的接口。

## 说明

依然没有真机验证。本版为纯诊断改进：把"看不到原因"变成"原因直接打出来"。
