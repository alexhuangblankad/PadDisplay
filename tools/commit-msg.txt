v0.5.0: 桌面模式（DeX / TNT 思路）—— 找到能真正打开它的开关

## 用户思路是对的，之前漏了它

参考项目 fox0001/android-desktop-mode 的 README 点明关键：
从 Android 10 起系统内置「桌面模式」，该模式下 App 可自由拖动位置、调整窗口大小。
开发者选项里勾选「启用可自由调整的窗口」+「强制使用桌面模式」即可启用。

## 关键发现：那两个勾就是 Global settings，Shizuku 能直接写

AOSP WindowManagerService 里：
  Settings.Global.DEVELOPMENT_FORCE_DESKTOP_MODE_ON_EXTERNAL_DISPLAYS
  Settings.Global.DEVELOPMENT_ENABLE_FREEFORM_WINDOWS_SUPPORT
  Settings.Global.DEVELOPMENT_FORCE_RESIZABLE_ACTIVITIES

WMS 的 SettingsObserver 实时监听：
  mForceDesktopModeOnExternalDisplaysUri -> updateForceDesktopModeOnExternalDisplays()
  mFreeformWindowUri -> updateFreeformWindowManagement()
后者会把 mAtmService.mSupportsFreeformWindowManagement 设为 true。

写这两个键 = 帮用户在开发者选项里打勾，不需要 root（WRITE_SECURE_SETTINGS，shell 持有）。

## 修正我之前的一个武断判断

此前探测 development_force_desktop_mode_on_external_displays 得到 -999（键不存在），
我判断为"本机没有这个设置"。实际上：
  Settings.Global.getInt(resolver, key, 0)   // 默认 0，键不存在也返回 0
键不存在只说明该开关从没被碰过，不代表不能设置。写入后就会存在。

## 关于鼠标的诚实说明

AOSP WindowManagerService 中该字段注释原文：
  - Enable system decorations and IME on external screen.
  - TODO: Show mouse pointer on external screen.
即 Android 官方在桌面模式里都还没做「在外接屏显示鼠标指针」。

因此：
- 外接屏成为真正的桌面（自由窗口、可拖动缩放）：能，这正是其用途
- 外接屏有系统装饰与输入法：能
- 鼠标指针显示在外接屏：AOSP 自己仍是 TODO
- 鼠标跨两块屏：需要 DisplayTopology，本机被关闭

不会宣称"开了桌面模式鼠标就能跨屏"。
