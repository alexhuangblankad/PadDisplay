v0.3.1: 读 Dextop 源码后的三处修正（输入绑定判定 / 拓扑事务号 / 键盘策略）

## 探测结论

DisplayTopology 类可用、TreeNode 类可用，但能力探测 supported=false：
系统返回 null，说明该 feature flag 在本机关闭，服务端 setDisplayTopology 是静默空操作。
这不是权限问题，是 ColorOS 未启用该能力，无法靠 App 绕过（要开需改系统 config，即 root）。

## 参考项目 Dextop 源码纠错三处

视频里的项目是 NarYuki/Dextop（GPL-3.0）。它自称支持"跨显示器指针路由"与
"鼠标键盘输入路由切换"，但对 ColorOS 的自评是"有限且不完整"。读源码后发现三处
直接纠正我方实现的地方：

### 1. 输入设备判定写错了（这是日志里绑定失败的真正原因）

Dextop 的 PhysicalDeviceRouting.eligibleDevices 用：
    device.id >= 0 && device.isExternal && device.descriptor.isNotBlank() && ...
InputDevice.isExternal() 是公共 API。而我用反射读 getLocation() 是否非空 —
在该 ROM 上返回空，于是 6 个输入设备全被过滤，报"没有可绑定的外接输入设备"。

现改为 isExternal + 鼠标/键盘类型筛选，并把不符合条件的设备全部列出，
便于判断是"没有外接设备"还是筛选条件不对。
另外用 InputDevice.getAssociatedDisplayId() 做读回验证（Dextop 用它判断绑定是否生效），
不再只看写入是否报错。

### 2. 拓扑事务号不该硬编码

Dextop 源码明确警告：transaction ids 在不同 Android 版本与 OEM 分支间不稳定，
新版本上旧的 id 可能指向 requestDisplayModes()（受 RESTRICT_DISPLAY_MODES 保护），
Never use a numeric fallback。

上一版用了硬编码 63/64，现改为从 IDisplayManager$Stub 读真实
TRANSACTION_getDisplayTopology / TRANSACTION_setDisplayTopology 常量；
读不到就判定不支持并明确报告，绝不退回数字。

### 3. 键盘不该绑定

Dextop 把鼠标与键盘分开控制（mouse/keyboard 两个参数）。原因是 Android 的设备关联
是静态的：把键盘绑到外屏后它只往外屏送键事件。
所以本版默认只绑鼠标、不绑键盘；键事件走焦点窗口，
两块屏按焦点各自接收键盘输入，更接近"选哪个屏就在哪里输入"。

## 能力边界（如实）

- 两个桌面：系统层面成立（用户已用 am start --display 验证满屏 4K）
- 鼠标能否操作外屏：修正了判定逻辑，是否放行需实测
- 键盘跟焦点：按上述策略处理，需实测
- 屏幕左右关系 / 鼠标自由跨屏拖拽：依赖 DisplayTopology，本机被 ROM 关闭，无法实现

### 新增文件

- InputRoutingController.kt 重构：isExternal 判定、读回验证、鼠标/键盘分离
- DisplayTopologyController.kt：事务号动态解析、去掉硬编码与强制解包

## 验证步骤

1. 查看输入设备列表，重点看有没有 external=true 的设备、是鼠标还是键盘
2. 绑定输入到外屏，看三级回退结果 + 读回验证那行
3. 把探测拓扑的完整输出发回

## 说明

依然没有真机验证。若输入绑定仍不生效，会明确告知"这条路在 ColorOS 上不通"，
并转向只做两个桌面（不追求鼠标跨屏）。
