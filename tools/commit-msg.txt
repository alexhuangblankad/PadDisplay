v0.6.0: MouseFlow 第一轮实验 —— 查清原生鼠标换屏的真实机制

## 修正上一版的错误结论

上一版说"桌面模式不解决鼠标问题"，是误读了 AOSP 注释。查证结果：

### setPointerDisplayId 存在，但外部调不到

  // NativeInputManagerService（native 本地接口，非 Binder 服务）
  /** Set the displayId on which the mouse cursor should be shown. */
  void setPointerDisplayId(int displayId);

全 AOSP 只有一处调用：
  // InputManagerService.setDisplayViewportsInternal()
  mNative.setPointerDisplayId(mWindowManagerCallbacks.getPointerDisplayId());

即 IMS 主动从 WMS 取值。它不是 Binder 服务，App / Shizuku / adb 都无法直接调用。

### 换屏能力系统自己就会做

取值逻辑 WMS.InputManagerCallback.getPointerDisplayId()：
  if (!mService.mForceDesktopModeOnExternalDisplays) {
      return DEFAULT_DISPLAY;                 // 桌面模式没开，光标只在内屏
  }
  for (...) {                                  // 找最上层 freeform 显示器
      if (displayContent.getWindowingMode() == WINDOWING_MODE_FREEFORM) {
          return displayContent.getDisplayId(); // 原生光标去这块屏
      }
  }
  return firstExternalDisplayId;

所以"原生鼠标出现在外接屏"的条件就是那两个 Global settings
（v0.5.0 已加入的桌面模式 + 自由窗口），不需要 setPointerDisplayId —— 系统自己会调。

## 本版新增 MouseFlow 实验卡片

按任务书要求：先做实验，不直接写完整功能。

- 探测原生指针所在屏：按 AOSP 同一套逻辑推演系统会把光标放哪及依据；
  枚举物理鼠标（Device ID / Name / Sources / Vendor / Product /
  External / AssocDisplayId / RelativeAxes）；打印各屏 windowingMode；
  给出 ADB 辅助诊断命令
- 强制鼠标到内屏 / 强制鼠标到外屏：用 injectInputEvent + setDisplayId 移动指针位置，
  坐标从 dumpsys window displays 的 cur=WxH 取，取不到就拒绝盲猜
- 失败时输出完整异常（SecurityException / RemoteException /
  NoSuchMethodException / Binder 错误）

## 按任务书调整方案优先级

接受"自绘假光标 + 注入会破坏 Moonlight"的判断：
- pointer capture / relative mouse mode：注入事件不是真实指针事件
- hover：系统不给注入事件点亮指针
- 滚轮 / 右键 / 游戏鼠标：自绘光标不参与系统指针语义

触控板已降级标注为"不推荐"并写明会破坏什么，推荐路线改为桌面模式 + MouseFlow。

## 测试顺序（本轮唯一关键问题）

1. 连外接屏 -> 一键开始
2. MouseFlow 实验 -> 探测原生指针所在屏（发回输出）
3. 桌面模式 -> 开启桌面模式
4. 重新插拔外接屏（必须，系统才会重算指针归属）
5. 看物理鼠标是否出现在外接屏上

第 5 步即任务书 Test A/B。成功则说明 ColorOS 底层 Pointer Routing 存在，
下一步才做边缘自动跨屏（edgeThreshold + switchCooldown，纯逻辑问题）。

## 说明

- 依然没有真机验证。
- 本轮未实现自动边缘跨屏，按任务书第十八条只做第一轮实验。
- 若第 5 步失败，需看探测输出判断断点：键写不进去（ROM 限制）、
  副屏未进 freeform、还是指针被强制留在内屏。
