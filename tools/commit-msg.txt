v0.4.0: 应用抽屉（外接屏的开始菜单）—— 修掉"只能开设置"

## 只能打开设置的原因（实现缺陷）

早先启动应用时写死了 com.android.settings/.Settings 这个组件，
所以外接屏上只能打开设置。另外那条代码用 am start -p <包名>，
而 am start 期望的是 component（-n），-p 不可靠。
因此只有显式给了 -n 的设置能成功。

## 本版修好：应用抽屉

主界面（不用进高级选项）新增「打开应用到外接屏」：
- 解析设备上所有应用的 launcher Activity 组件
- 列出应用清单，每个应用后有「外屏」「内屏」两个按钮
- 外屏走 am start --display <外接屏id> -n <组件>（系统自带能力，已验证可满屏 4K）

底层是 am start --display，这次用正确的 component 形式并覆盖所有应用。

## 鼠标跨屏：明确做不到，原因已查清

AOSP 里指针跨屏能力来自 DisplayTopology：
    if (mFlags.isDisplayTopologyEnabled()) {
        mInputManagerInternal.setDisplayTopology(graph);
    }
而该机探测结果为 supported=false、系统返回 null，说明 ColorOS 关闭了该 feature flag。
服务端 mDisplayTopologyCoordinator == null，setDisplayTopology 是静默空操作。
要打开必须改系统 framework flag，需要 root，超出用户设定的边界。

因此：
- 两个桌面（外屏独立跑应用）：可以，本版应用抽屉让它真正可用
- 鼠标不飘逸：用户已验证修好
- 分辨率：4K@60 本就是外屏原生模式
- 鼠标跨屏拖拽 / 两屏左右上下位置：需要 DisplayTopology，非 root 无解

## 若要鼠标跨屏，只有两条路

1. root 后打开该 feature flag（用户已表示不做 root）
2. 改用手势控制：参考 AdaptiveScreenPlus 的做法，在平板上做触控板页面，
   用 IInputManager.injectInputEvent + MotionEvent.setDisplayId 把触摸注入到外接屏，
   并自绘光标浮层（系统只给真实鼠标画指针）。这不是"鼠标跨屏"，
   而是"用平板当外接屏的触控板"。等用户选择。
